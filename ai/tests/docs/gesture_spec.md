# Gesture Interaction Spec

## 목적

인터뷰 진행 중 버튼 입력 외에 손 제스처를 보조 입력 수단으로 제공한다.

- 다음 질문: `Hand Landmarker` 기반 swipe 제스처
- 종료: 기본 canned gesture 기반 종료 요청
- 기존 버튼은 항상 fallback으로 유지

## 범위

이 문서는 프론트와 AI가 공통으로 참조하는 제스처 동작 명세를 정의한다.

- 프론트: 카메라 입력, 추론 루프, 상태 연동, UI
- AI: gesture 의미 정의, 판정 기준, 오탐 방지 규칙
- 백엔드: 기존 인터뷰 API 재사용, 로깅, 중복 요청 방지

## 인터뷰 상태별 허용 규칙

제스처는 인터뷰 상태에 따라 다르게 허용한다.

| 상태 | 설명 | swipe 허용 | 종료 gesture 허용 |
| --- | --- | --- | --- |
| `CONNECTING` | 인터뷰 연결 중 | 아니오 | 아니오 |
| `AI_SPEAKING` | 질문 텍스트 표시 및 TTS 재생 중 | 아니오 | 예 |
| `USER_RECORDING` | 사용자 답변 녹음 중 | 예 | 예 |
| `WAITING_AI` | 답변 제출 후 다음 질문 생성 대기 중 | 아니오 | 아니오 |

## 다음 질문 제스처 정의

다음 질문은 동적 swipe 제스처로 정의한다.

- 입력 방식: `Hand Landmarker`
- 기본 방향: 사용자 기준 오른쪽에서 왼쪽으로 이동
- 권장 UX: 책 넘기듯 한 방향으로 짧고 분명하게 손을 이동
- 인식 대상 손: 화면 내 가장 신뢰도 높은 단일 손
- 권장 손 모양: 열린 손바닥 또는 손가락이 충분히 펼쳐진 상태

다음 질문 판정 조건의 핵심은 아래와 같다.

- 짧은 시간 창 안에서 x축 이동량이 충분히 커야 한다.
- 이동 방향이 일관되어야 한다.
- y축 흔들림은 제한되어야 한다.
- 손이 화면 안에 안정적으로 유지되어야 한다.
- 한 번 인식되면 즉시 재인식되지 않도록 cooldown을 둔다.

## 종료 제스처 정의

종료는 기본 canned gesture 중 하나를 사용한다.

- 입력 방식: canned gesture
- 기본 후보: `Victory`
- 대체 후보: `Thumb_Up`
- 비권장: `Open_Palm`, `Closed_Fist`

종료는 다음 질문보다 오동작 비용이 크므로 안전장치를 둔다.

- 제스처를 일정 시간 이상 유지해야 한다.
- 추가 버튼 확인 대신 2단계 hold 방식을 사용한다.
- 인터뷰 진행 중 자연스러운 손짓과 겹치는 gesture는 피한다.

## 액션 매핑

| 제스처 | 액션 | 비고 |
| --- | --- | --- |
| swipe | 다음 질문 진행 | 기존 버튼과 동일한 흐름 호출 |
| `Victory` 1차 hold | 종료 후보 | 안내 UI 노출 |
| `Victory` 2차 hold | 인터뷰 종료 | 기존 종료 버튼과 동일한 흐름 호출 |

## UX 원칙

- 진행 중 버튼과 종료 버튼은 항상 노출한다.
- 버튼은 제스처 인식 실패 시 사용할 수 있는 보조 수단으로 유지한다.
- 제스처는 보조 입력 수단이다.
- 사용자가 제스처를 인식할 수 있도록 간단한 안내 문구를 제공한다.
- 종료 액션은 항상 보수적으로 처리한다.
- 오탐보다 미탐이 더 낫다는 원칙으로 threshold를 설정한다.

## 종료 2단계 UX

종료는 추가 버튼 확인 없이 `Victory` hold를 두 번 거치는 방식으로 처리한다.

1. `Victory` 1차 hold 감지
2. 안내 UI 문구 표시
3. `Victory`를 다시 일정 시간 유지하면 종료

권장 안내 문구는 아래와 같다.

- 1차 감지: `브이 제스처가 감지되었습니다. 종료하려면 한 번 더 유지하세요.`

## 비목표

이번 단계에서 아래 항목은 범위에서 제외한다.

- 별도 gesture 학습 모델 개발
- 서버 측 실시간 손 제스처 추론
- 복수 손 동시 인식 기반 상호작용
- 제스처만으로 전체 인터뷰 UI를 완전히 대체하는 것
