# Share Board Question Scenarios

## 1. 시나리오 A: 방문자가 질문을 남긴다

1. 방문자가 공유 보드 상세 화면에 진입한다.
2. 북마크 보드와 분리된 질문 보드 영역에서 "질문 남기기" UI를 연다.
3. 질문 내용을 입력한다.
4. 저장 요청을 보낸다.
5. 시스템은 질문을 질문 보드에 연결해 저장한다.
6. 저장 성공 시 질문 포스트잇이 질문 보드에 노출된다.

기대 결과:

- 보드 주인은 이후 해당 질문을 확인할 수 있다.
- 질문 작성자는 자신의 질문에 대해 수정/삭제 권한을 가진다.

## 2. 시나리오 B: 작성자가 자신의 질문을 수정한다

1. 작성자는 자신이 남긴 질문 목록 또는 질문 카드에서 수정 액션을 누른다.
2. 기존 질문 내용을 수정한다.
3. 저장 요청을 보낸다.
4. 시스템은 작성자 본인 여부를 검증한다.
5. 성공 시 수정된 내용과 수정 시간이 반영된다.

예외:

- 작성자가 아니면 수정할 수 없다.
- 이미 인터뷰 시작에 사용된 질문은 수정할 수 없다.

## 3. 시나리오 C: 작성자가 자신의 질문을 삭제한다

1. 작성자는 자신이 남긴 질문에서 삭제 액션을 누른다.
2. 시스템은 작성자 본인 여부를 검증한다.
3. 성공 시 질문은 목록에서 제거되거나 삭제 상태로 처리된다.

예외:

- 작성자가 아니면 삭제할 수 없다.
- 인터뷰 시작에 사용된 질문은 작성자가 삭제할 수 없다.
- 인터뷰 시작에 사용된 질문은 보드 주인만 삭제할 수 있다.

## 4. 시나리오 D: 보드 주인이 질문 보드를 확인한다

1. 보드 주인은 자신의 공유 보드 화면에서 방문자 질문 보드를 연다.
2. 질문 작성자 닉네임, 질문 내용, 작성 시각을 확인한다.
3. 원하는 질문을 선택한다.

기대 결과:

- 보드 주인은 다음 인터뷰의 시작점 후보를 쉽게 확인할 수 있어야 한다.

## 5. 시나리오 E: 보드 주인이 질문을 기반으로 인터뷰를 시작한다

1. 보드 주인이 질문 하나를 선택한다.
2. 시스템은 해당 질문을 인터뷰 시작용 입력값으로 전달한다.
3. 새 인터뷰 생성 또는 인터뷰 준비 화면으로 이동한다.
4. 질문 포스트잇에는 `인터뷰 진행됨` 상태가 표시된다.

후속 처리 후보:

- 질문 상태를 `SELECTED` 또는 `USED`로 변경
- 어떤 인터뷰에 사용되었는지 연결 정보 저장

## 6. 시나리오 F: 권한 없는 사용자의 수정/삭제 시도

1. 다른 방문자가 남의 질문에 수정 요청을 보낸다.
2. 시스템은 작성자 불일치를 감지한다.
3. 권한 없음 에러를 반환한다.

삭제는 예외적으로 보드 주인도 가능하다.

## 7. 시나리오 G: 보드 주인이 부적절한 질문을 삭제한다

1. 방문자가 질문 보드에 질문을 남긴다.
2. 보드 주인이 해당 질문을 확인한다.
3. 보드 주인이 운영 목적으로 삭제 액션을 수행한다.
4. 시스템은 보드 소유자 여부를 검증한다.
5. 성공 시 질문은 삭제 처리된다.
## 8. 시나리오 H: 접근 불가 보드에서 질문 작성 시도

1. 사용자가 비공개 또는 접근 권한이 없는 공유 보드에 접근한다.
2. 시스템은 보드 열람 권한 또는 질문 작성 권한을 검증한다.
3. 권한이 없으면 질문 작성 자체를 막는다.

## 9. 시나리오 I: 빈 질문 또는 너무 긴 질문 입력

1. 사용자가 빈 문자열, 공백만 있는 문자열, 허용 길이를 초과한 문자열을 입력한다.
2. 시스템은 유효성 검사 에러를 반환한다.
3. 프론트는 입력 에러 메시지를 노출한다.
