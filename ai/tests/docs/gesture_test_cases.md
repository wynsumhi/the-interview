# Gesture Test Cases

## 목적

이 문서는 제스처 기반 인터뷰 제어 기능의 검증 시나리오를 정리한다.
주 목적은 오탐과 미탐을 줄이고, 인터뷰 흐름이 깨지지 않는지 확인하는 것이다.

## 테스트 원칙

- 버튼 fallback은 항상 동작해야 한다.
- 진행 중 버튼과 종료 버튼은 항상 노출되어야 한다.
- 제스처 인식 실패가 인터뷰 진행을 막아서는 안 된다.
- 종료는 다음 질문보다 더 보수적으로 검증한다.
- 종료는 추가 버튼 확인 없이 `Victory` 2단계 hold로 검증한다.
- 밝은 환경과 어두운 환경을 모두 포함한다.

## 정상 케이스

### TC-01 정상 swipe 우측

- 상태: `USER_RECORDING`
- 조건: 열린 손으로 짧고 분명하게 우측 swipe
- 기대 결과: 다음 질문 동작 1회 발생

### TC-02 정상 swipe 좌측

- 상태: `USER_RECORDING`
- 조건: 열린 손으로 짧고 분명하게 좌측 swipe
- 기대 결과: 다음 질문 동작 1회 발생

### TC-03 정상 종료 gesture

- 상태: `USER_RECORDING`
- 조건: `Victory`를 1초 이상 유지
- 기대 결과: 종료 후보 UI 표시

### TC-04 정상 종료 2단계 hold

- 상태: `USER_RECORDING`
- 조건: `Victory` 1차 hold 후 안내 UI가 보이는 상태에서 `Victory`를 다시 1초 이상 유지
- 기대 결과: 인터뷰 종료 1회 실행

### TC-05 AI 질문 중 종료 gesture

- 상태: `AI_SPEAKING`
- 설명: 질문 텍스트 표시 및 TTS 재생 중
- 조건: `Victory`를 1초 이상 유지
- 기대 결과: 종료 후보 UI 표시

## 오탐 방지 케이스

### TC-06 말하면서 자연스럽게 손 흔들기

- 상태: `USER_RECORDING`
- 조건: 손을 여러 방향으로 천천히 움직임
- 기대 결과: swipe 미인식

### TC-07 천천히 손 이동

- 상태: `USER_RECORDING`
- 조건: 화면 안에서 손을 천천히 좌우 이동
- 기대 결과: swipe 미인식

### TC-08 손을 위아래로 흔들기

- 상태: `USER_RECORDING`
- 조건: y축 중심 움직임이 큰 경우
- 기대 결과: swipe 미인식

### TC-09 부분 가림

- 상태: `USER_RECORDING`
- 조건: 손 일부가 화면 밖으로 나감
- 기대 결과: swipe 미인식 또는 무시

### TC-10 자연스러운 open palm

- 상태: `USER_RECORDING`
- 조건: 대화 중 손바닥을 잠깐 보임
- 기대 결과: 종료 미발생

### TC-11 1차 종료 후보 후 손 내림

- 상태: `USER_RECORDING`
- 조건: `Victory` 1차 hold 후 손을 내림
- 기대 결과: 종료 확정되지 않음, 종료 후보 상태 해제

### TC-12 자연스러운 브이 포즈 짧게 노출

- 상태: `USER_RECORDING`
- 조건: `Victory`가 짧게 감지되지만 1차 hold time 미만
- 기대 결과: 종료 후보 UI 미표시

## 상태 제어 케이스

### TC-13 `WAITING_AI` 중 swipe

- 상태: `WAITING_AI`
- 설명: 답변 제출 후 다음 질문 생성 대기 중
- 조건: swipe 시도
- 기대 결과: 무시

### TC-14 `CONNECTING` 중 종료 gesture

- 상태: `CONNECTING`
- 조건: 종료 gesture 시도
- 기대 결과: 무시

### TC-15 `AI_SPEAKING` 중 swipe

- 상태: `AI_SPEAKING`
- 조건: swipe 시도
- 기대 결과: 무시

## 성능 케이스

### TC-16 저조도 환경

- 조건: 실내 조명이 어두운 환경
- 기대 결과: 오탐 없이 최소 기능 유지

### TC-17 역광 환경

- 조건: 창문 배경 등 역광
- 기대 결과: 잘못된 종료 또는 다음 질문 발생 금지

### TC-18 저사양 환경

- 조건: 프레임 드롭이 있는 환경
- 기대 결과: UI 멈춤 없이 버튼 fallback 유지

## 회복 케이스

### TC-19 손 미검출 후 재진입

- 조건: 손이 화면 밖으로 나갔다가 다시 들어옴
- 기대 결과: 이전 궤적과 이어서 잘못 인식하지 않음

### TC-20 연속 swipe 시도

- 조건: 매우 빠르게 여러 번 swipe
- 기대 결과: cooldown에 따라 1회만 반영

### TC-21 제스처 실패 후 버튼 사용

- 상태: `USER_RECORDING`
- 조건: swipe 또는 `Victory`가 인식되지 않는 상황에서 버튼 클릭
- 기대 결과: 진행 중 버튼과 종료 버튼으로 각각 정상 동작

## 수집 권장 메모

수동 테스트 시 아래 메모를 같이 남긴다.

- 테스트 환경
- 브라우저
- 카메라 해상도
- 조명 상태
- 성공 여부
- 오탐 여부
- 반응 속도 체감
- 특이사항

## 릴리스 전 최소 통과 기준

- 정상 swipe와 종료 gesture 기본 동작 확인
- `Victory` 2단계 hold 종료 동작 확인
- `WAITING_AI` 상태에서 오동작 없음
- 종료 오탐 없음
- 제스처 실패 상황에서도 버튼 fallback 정상 동작
- 저조도 또는 역광 환경에서 심각한 오동작 없음
