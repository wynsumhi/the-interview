# Share Board Question Frontend Flow

## 1. 화면 목적

공유 보드를 보는 사용자가 자연스럽게 질문을 남기고, 보드 주인은 그 질문을 확인해 다음 인터뷰로 이어갈 수 있어야 한다.

## 2. 화면 구성 제안

### 2.1 공유 보드 화면

현재 포스트잇 보드 UI는 유지한다.

질문 기능은 북마크 보드와 별도의 질문 포스트잇 보드로 분리한다.

이유:

- 북마크 보드는 과거 인터뷰 북마크 아카이브다.
- 질문 보드는 미래 인터뷰를 여는 질문 포스트잇 보드다.
- 두 보드는 성격과 액션이 다르다.

권장 UI:

- 상단 또는 메인에 북마크 보드
- 하단 또는 별도 섹션에 질문 보드
- "이 사람에게 질문 남기기" CTA 버튼 + 질문 포스트잇 입력

### 2.2 질문 입력

입력 요소:

- 멀티라인 텍스트 영역
- 글자 수 표시
- 등록 버튼

상태:

- 기본
- 입력 중
- 저장 중
- 저장 성공
- 저장 실패

### 2.3 질문 포스트잇 보드

각 항목 표시 정보:

- 작성자 닉네임
- 질문 내용
- 작성 시간
- 본인 질문 여부
- 수정됨 여부
- 보드 주인 삭제 가능 여부
- 인터뷰 진행 여부 배지

노출 정책:

- 공유 보드 접근 권한이 있는 모든 방문자는 질문 포스트잇 보드를 볼 수 있다.

본인 질문일 때만 노출:

- 수정 버튼
- 삭제 버튼

보드 주인일 때도 노출:

- 삭제 버튼

예외:

- `인터뷰 진행됨` 상태에서는 작성자에게 수정/삭제 버튼을 노출하지 않는다.
- `인터뷰 진행됨` 상태에서는 보드 주인에게만 삭제 버튼을 노출한다.

## 3. 화면 흐름

### 3.1 방문자 기준

1. 공유 보드 진입
2. 질문 남기기 영역 열기
3. 질문 작성
4. 등록 성공 후 목록 반영
5. 본인 질문이면 수정/삭제 가능

### 3.2 보드 주인 기준

1. 자신의 공유 보드 진입
2. 질문 목록 열기
3. 질문 확인
4. 인터뷰 시작 액션 선택

## 4. 프론트 상태 관리 초안

필요 상태:

- `questions`
- `isQuestionFormOpen`
- `isSubmitting`
- `editingQuestionId`
- `draftContent`
- `cursor`
- `hasNext`

## 5. API 연동 순서 초안

1. 보드 진입 시 질문 보드 조회
2. 질문 등록 시 생성 API 호출
3. 수정 시 수정 API 호출
4. 삭제 시 삭제 API 호출
5. 보드 주인이 질문 선택 시 인터뷰 시작 API 또는 질문 선택 API 호출

## 6. UX 권장사항

- 질문 등록 직후 목록을 낙관적으로 갱신해도 좋다.
- 삭제는 확인 모달 또는 2단계 확인이 있으면 좋다.
- 수정 중인 질문은 인라인 편집으로 처리하는 편이 자연스럽다.
- 북마크 보드와 질문 보드의 시각 계층을 분리해야 한다.
- `인터뷰 진행됨` 상태를 포스트잇 배지나 스탬프 형태로 명확히 보여주는 것이 좋다.

## 7. Open Questions

1. 질문 보드를 같은 페이지 하단에 둘지, 별도 탭으로 둘지
2. 인터뷰 시작 액션을 질문 포스트잇에 둘지, 상세 모달에 둘지
